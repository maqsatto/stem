# Известные ограничения MVP

Ниже — осознанные границы текущей версии. Они не блокируют учебный сценарий,
но должны быть учтены при приёмке и развитии.

## Контент и методика

- Все seed-материалы — **демонстрационные** (`is_demo=true`). Тексты,
  индикаторы, критерии и ключи диагностик не являются утверждённой научной
  методикой.
- Пороговые уровни и scoring-конфигурация диагностик — демо-значения; их
  должен утвердить методист/научный руководитель.
- Pre/post сравниваются только внутри одного `methodology_key`. Смешивание
  методик намеренно запрещено.
- Основные пользовательские экраны доступны на казахском и английском; часть
  административных и учительских подписей ещё переведена не полностью. Русский
  интерфейс не входит в текущий набор языков.
- Переводы демо-материалов включены; материалы, добавленные заказчиком,
  переводятся вручную через CMS. Для незаполненных полей используется оригинал.

## Аккаунты и коммуникации

- Нет отправки email/SMS. Временные пароли приглашённых и сброшенные пароли
  показываются один раз в интерфейсе — их нужно передать вручную по
  безопасному каналу.
- Нет самостоятельного восстановления пароля по email; пароль сбрасывает
  администратор.
- Ученики регистрируются сами (можно отключить
  `ALLOW_STUDENT_REGISTRATION=false`); подтверждение email отсутствует.

## Инфраструктура и масштабирование

- Rate limiting входа — in-process, рассчитан на один backend-процесс. При
  нескольких репликах нужен Redis/общий store.
- Файлы хранятся на локальном volume, без S3/CDN и без антивирусного
  сканирования. Проверяются расширение, MIME, magic bytes и размер.
- Один узел PostgreSQL и один backend; HA, репликация и автоматический
  failover не настроены.
- TLS/домен обеспечиваются внешним reverse proxy; в compose входит только
  HTTP-nginx.
- Нет фоновых задач (напоминания о дедлайнах, рассылки, пересчёт отчётов).

## Frontend

- Production-бандл около 1.2 МБ (gzip ~334 КБ); Vite предупреждает о размере
  чанка. Код-сплиттинг не сделан.
- Нет Playwright/E2E-тестов; покрытие Vitest ограничено формами, рубрикой и
  утилитами.
- Нет офлайн-режима и PWA.
- Доступность проверена базово (семантические элементы, aria-label у ключевых
  полей), полный аудит WCAG не проводился.
- Перевод интерфейса ещё не завершён на всех экранах; часть строк находится прямо в компонентах.

## Безопасность

- HTML очищается на сервере и при просмотре в браузере. Редактор использует
  textarea с HTML-панелью инструментов и предварительным просмотром, без WYSIWYG.
- Нет 2FA для администраторов.
- Аудит-журнал доступен только администратору и не имеет экспорта.
- Секреты в `.env` — стандартный для MVP подход; для production рекомендуется
  внешний secret manager.
- Нет CSP-заголовка (базовые security headers nginx/FastAPI выставлены).

## Эксплуатация

- Резервное копирование — скрипты + cron; автоматическая проверка восстановления
  не встроена.
- Мониторинг ограничен healthcheck-ами и логами; метрики/алерты нужно
  подключить внешне.
- Нет миграции данных из другой LMS и импорта контента из файлов.
- OpenAPI включён по умолчанию; в production его можно отключить
  (`DOCS_ENABLED=false`).

## Что считается следующим шагом

1. Утвердить методику и заменить демо-контент.
2. Добавить Playwright E2E и CI (lint, tests, build, compose smoke).
3. Вынести файлы в S3, добавить антивирус и резервное копирование с проверкой.
4. Добавить email-приглашения и самостоятельный сброс пароля.
5. При росте нагрузки — Redis rate limiting, несколько backend-реплик,
   управляемая PostgreSQL.
